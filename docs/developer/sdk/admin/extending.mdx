The Admin SDK client exposes a `request` method — the same function that powers `client.products.list()`, `client.orders.get()`, and every other built-in resource. Use it to call any Admin API endpoint, including ones added by an extension gem that doesn't ship its own client.

```typescript
import { createAdminClient } from '@spree/admin-sdk'
import type { PaginatedResponse } from '@spree/admin-sdk'

const client = createAdminClient({
  baseUrl: 'https://api.mystore.com',
  token: 'sk_YOUR_SECRET_KEY', // or a JWT from /auth/login
})

interface Brand {
  id: string
  name: string
  slug: string | null
  description: string | null
  logo_url: string | null
}

// Paths are relative to /api/v3/admin
const brands = await client.request<PaginatedResponse<Brand>>('GET', '/brands')
const brand = await client.request<Brand>('GET', '/brands/brand_2X9aQf7kEw')
```

`client.request` uses the same auth headers (secret API key *or* JWT, whichever was configured at client creation), retry logic, and base URL as every other resource on the client. The 401 → refresh → retry handshake that's wired up for the dashboard's user session applies to your custom endpoint too.

## Mutations

POST/PATCH/DELETE work the same way — pass `{ body }` for the request payload:

```typescript
const created = await client.request<Brand>('POST', '/brands', {
  body: { name: 'Acme', slug: 'acme', description: 'Quality goods since 1953' },
})

const updated = await client.request<Brand>('PATCH', `/brands/${created.id}`, {
  body: { description: 'New tagline' },
})

await client.request<void>('DELETE', `/brands/${created.id}`)
```

## Ransack filters and pagination

`client.request` sends `params` as the query string as they are, so write filters the way the Admin API reads them, as `q[<attribute>_<predicate>]`:

```typescript
const result = await client.request<PaginatedResponse<Brand>>('GET', '/brands', {
  params: {
    page: 2,
    limit: 25,
    'q[name_cont]': 'nike',
    sort: '-created_at',
  },
})
```

The built-in `list` methods take filters as plain keys and wrap them for you — `client.products.list({ name_cont: 'nike' })` sends `q[name_cont]=nike`. To get the same in a wrapper of your own, define it as an extension (below): its `listParams` is that transform.

## Shipping a client for an extension

An extension that adds Admin API endpoints ships a typed client for them as an npm package. The package is generated from the extension: `spree sdk generate` writes one SDK extension per resource, with a method per documented endpoint, and the types they take and return. An app adds them to its client with `extend`:

```typescript
import { createAdminClient } from '@spree/admin-sdk'
import { extendAdminClient } from 'my-quotes-extension'

const client = extendAdminClient(createAdminClient({ baseUrl, secretKey }))

const quote = await client.quotes.send('quote_1', { valid_until: '2026-12-01' }) // typed as Quote
client.products.list()                            // the built-in resources are unchanged
```

- The extension's calls use the client's own request function: paths are relative to `/api/v3/admin`, with the same auth, headers, retries and defaults as the built-in resources.
- `extend` returns a new client and leaves the original as it was. Both share their settings, so a token or locale set on either one applies to the other. `extendAdminClient` adds every namespace the package has; `client.extend(quotes)` adds one.
- An extension adds a new namespace only. `extend` throws a `TypeError` for a name the client already has (`products`, or the same extension twice) and for an extension of another API.
- The package lists `@spree/admin-sdk` as a peer dependency, so the app's own client is the one extended.

### Generating the client

The extension documents its endpoints with rswag specs (see [documenting your extension's endpoints](/developer/mcp/custom-tools#documenting-your-extensions-endpoints)); its serializers describe what they return. In the package, name the extension in `package.json`:

```json package.json
{
  "name": "my-quotes-extension",
  "peerDependencies": { "@spree/admin-sdk": "^6.0.3" },
  "spree": { "extension": "../my_extension" }
}
```

and run, from the package:

```bash
spree sdk generate           # after changing an endpoint or a serializer
spree sdk generate --check   # in CI: fails when the generated files are out of date
```

It runs the extension's `rake spree:openapi:generate` and `rake spree:sdk:serializer_types` (build its test app first, with `bundle exec rake test_app`), then writes `src/generated/<api>/`:

| File | From |
| --- | --- |
| `client.ts` | one extension per resource: `list`, `get`, `create`, `update`, `delete` and each action, camel-cased (`PATCH /quotes/{id}/send` → `quotes.send()`), documented with the operation's summary and description |
| `params/` | the request bodies (`request_body_for`) |
| `filters.ts` | the list filters (`filter_parameters_for`) |
| `types/`, `spree.ts` | the response types, from the serializers |

`spree.ts` re-exports the SDK's types beside the package's own, so a `Quote` that nests an order uses the SDK's `Order` rather than a copy. Give the extension's serializers names the SDK does not use: an `OrderSerializer` would clash with the SDK's `Order`, and two serializers of one API ending in the same name are refused. A response with no schema in the document is typed by its resource's name (`quotes` → `Quote`). Two operations that would make one method are refused; give one an `operationId` to name it. Pass `--no-backend` to generate from the committed documents and types without running the rake tasks.

Re-export what the package offers from its own entry point, and wrap or rename methods there if you want a different shape:

```typescript src/index.ts
export * from './generated/admin/client'
export type * from './generated/admin/spree'
```

### Defining one by hand

For a single endpoint, or one the document does not describe, define the extension yourself. `build` gets the client's `request`, plus `listParams` and `readParams` to build list and read queries the way the built-in methods do:

```typescript
import { defineAdminExtension } from '@spree/admin-sdk'

export const quotes = defineAdminExtension('quotes', ({ request }) => ({
  get: (id: string) => request<Quote>('GET', `/quotes/${id}`),
}))
```
