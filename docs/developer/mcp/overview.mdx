Spree can host a [Model Context Protocol](https://modelcontextprotocol.io) server of its own, so an MCP client — Claude Desktop, claude.ai, Claude Code, Cursor, an in-house agent — can work in your store by talking to it: find products, answer "what did we sell in Germany last month", cancel an order, mark a shipment delivered, add a market.

It runs inside your Spree application. There is no separate service to deploy, and every request goes through the same tenancy, permission and validation rules as the API itself. An agent does exactly what the person who connected it allows, and nothing else.

## The endpoint

```text
https://your-store.com/api/v3/admin/mcp
```

The back office: the catalog, orders, reporting and store setup, for staff and the agents they connect.

<Note>
  One endpoint, one audience. The tools an agent is offered here are the back office's, and a merchant's grant is measured against their own staff permissions — so an agent reaches exactly what the person who connected it can reach.
</Note>

## How it fits together

An MCP client speaks JSON-RPC to one endpoint. Behind it:

- **Tools** are what the agent can do — one per operation, named for the merchant's language rather than the API's. [The reference](/developer/mcp/tools) lists all 58.
- **Resources** are files the client can fetch. Finished exports, as CSV.
- **Consent** decides what any of it reaches. A merchant signs in and approves specific permissions; the agent is never offered a tool outside them.

Every tool reaches data by making a real API request inside the process — the same routing, authentication, record-level authorization and serialization an external client gets. A guard added to the API protects agents without anyone copying it into the tool layer.

## What it is not

**Not the documentation server.** The [docs MCP server](/developer/agentic/mcp) lets an agent read Spree's documentation while writing code against it. This one operates a live store. They are unrelated and you can use both.

**Not a replacement for the API.** An agent is good at a merchant's request in words. A scheduled job, a data pipeline or a storefront should call the [Admin API](/api-reference/admin) or the [`spree api` CLI](/developer/cli/admin-api) directly.
