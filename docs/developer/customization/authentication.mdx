Spree ships with built-in, gem-owned authentication models — `Spree::Customer` (storefront customers) and `Spree::AdminUser` (staff) — backed by Rails' [`has_secure_password`](https://api.rubyonrails.org/classes/ActiveModel/SecurePassword/ClassMethods.html). If you installed Spree following the [Quickstart guide](/developer/quickstart), authentication is already set up and you can skip this page.

You only need the steps below if you want Spree to authenticate against your **own** user model — for example a shared/SSO user table, or an existing application you're adding Spree to.

## Using your own user model

Point `Spree.customer_class` (and optionally `Spree.admin_user_class`) at your model in `config/initializers/spree.rb`:

```ruby
Spree.customer_class = 'MyApp::User'
```

> `Spree.user_class` still works as a deprecated alias for `Spree.customer_class` and will be removed in Spree 6.1.

On that model, include the Spree customer concern — a single include that brings in addresses, payment sources, orders, wishlists, and store credit — and add `has_secure_password`:

```ruby
# app/models/my_app/user.rb
class MyApp::User < ApplicationRecord
  has_secure_password validations: false

  include Spree::CustomerMethods
end
```

`Spree::CustomerMethods` absorbs the former `Spree::UserAddress` and `Spree::UserPaymentSource` concerns, so this single include is all that's required.

### Keeping an existing password column

If your model already stores its password digest in a column other than `password_digest` — for example the `encrypted_password` column from a Devise-based app — bridge it so `has_secure_password` can read it. Either alias the column:

```ruby
class MyApp::User < ApplicationRecord
  has_secure_password validations: false
  include Spree::CustomerMethods

  alias_attribute :password_digest, :encrypted_password
end
```

or rename the column to `password_digest` in a migration. A plain bcrypt digest (such as Devise's `encrypted_password` with no pepper configured) is read directly by `has_secure_password`, so existing passwords keep working with no reset.

## Custom authentication providers

Spree authenticates through pluggable strategies — `Spree.store_authentication_strategies` and `Spree.admin_authentication_strategies` — which default to email + password. To plug in an external provider (Auth0, Clerk, SSO, and so on), implement a `Spree::Authentication::Strategies::BaseStrategy` subclass and register it. See [Custom API authentication](/developer/how-to/custom-api-authentication) for a worked example.
