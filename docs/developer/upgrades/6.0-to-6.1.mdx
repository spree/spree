## How to upgrade

<CodeGroup>

```bash Spree CLI (Docker)
spree upgrade
```

```bash Without Spree CLI
# cd backend if you're in the monorepo root
bundle update
bundle exec rake spree:install:migrations && bin/rails db:migrate
bundle exec rake spree:upgrade
```

</CodeGroup>

`spree:upgrade` adds the built-in saved reports to any store that does not have them yet, such as a store upgraded from 5.6. Re-running it is safe.

## Behavioral changes

### Seeds create only the store and its first admin

`db:seed` now creates only what has no Admin API: the store, its admin role, its first publishable key and, with `ADMIN_EMAIL` and `ADMIN_PASSWORD`, the first admin. The defaults a store trades with are [store defaults](/developer/cli/configurator#store-defaults), deployed through the Admin API by first-run setup, `spree init` or `spree config provision`. They include tax categories, the wholesale channel and customer group, the return and refund reasons, store credit, digital delivery, the warehouse and the delivery zones. The built-in saved reports are now created with the store.

An existing store keeps every record its seeds created, so upgrading changes nothing in it. What changes is a new install, or a script that runs `db:seed` and then expects the defaults to be there: deploy them afterwards with `spree config provision`. Do not run `spree config provision` on a store that already has its defaults; it would add *Domestic* and *International* zones and a default tax category beside the ones the store already uses.

`spree:load_sample_data` now refuses a store that never got its defaults, and names the command that deploys them.

### Deprecated

These keep working in 6.1 but print a deprecation warning, and are removed in 6.2:

| Deprecated | Replacement |
| --- | --- |
| `Spree::Seeds::StoreResources` and the services it ran (`Spree::Seeds::TaxCategories`, `Spree::Seeds::Channels`, `Spree::Seeds::ReturnsEnvironment` and the rest) | They no longer create anything. Deploy the [store defaults](/developer/cli/configurator#store-defaults) with `spree config provision` |
| `Spree::Stores::ProvisionDefaults` | It no longer creates anything. `Spree::Store#relocate` moves a store and its default market to another country; `spree config provision` deploys its defaults |
| The `spree:install` generator's `--sample` option and the Rails application template's `LOAD_SAMPLE_DATA` | Both are ignored, because sample data needs a store that finished setup. Load it afterwards with `spree:load_sample_data` |
