Spree uses a separate model for admin/staff accounts (`Spree::AdminUser`) from storefront customers (`Spree::Customer`) — the default since Spree 5.2. Both are gem-owned and backed by [`has_secure_password`](https://api.rubyonrails.org/classes/ActiveModel/SecurePassword/ClassMethods.html); the admin dashboard authenticates against the Admin API with JWT access + refresh tokens, so no setup is required for the default.

You only need the steps below if you want the admin to authenticate against your **own** admin model.

## Using your own admin model

Point `Spree.admin_user_class` at your model in `config/initializers/spree.rb`:

```ruby
Spree.admin_user_class = 'MyApp::AdminUser'
```

On that model, include the admin concern (roles, permissions, store access) and add `has_secure_password`:

```ruby
# app/models/my_app/admin_user.rb
class MyApp::AdminUser < ApplicationRecord
  has_secure_password validations: false

  include Spree::AdminUserMethods
end
```

If the model keeps an existing password column (for example `encrypted_password`), bridge it as described in [Authentication](/developer/customization/authentication#keeping-an-existing-password-column).

The admin dashboard signs in through the Admin API auth endpoints (`POST /api/v3/admin/auth/login`, plus `refresh` and `logout`); custom providers plug in via `Spree.admin_authentication_strategies` (see [Custom authentication providers](/developer/customization/authentication#custom-authentication-providers)).
