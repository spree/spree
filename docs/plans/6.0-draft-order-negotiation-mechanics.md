# Draft Order Negotiation Mechanics (Manual Line Pricing + Cart Copy)

**Status:** Draft — design finalized 2026-08-30, nothing built
**Target:** Spree 6.0 (retargeted 2026-08-30: the cart→draft copy moved from 6.1 into 6.0 so the Enterprise quotes product needs nothing beyond 6.0 GA)
**Depends on:** Cart/Order split (6.0-cart-order-split.md), Third-Party Pricing (6.0-third-party-pricing-inventory.md — `price_source`), Service Workflows (6.0-service-workflows.md)
**Author:** Damian + Claude
**Last updated:** 2026-08-30

## Summary

Draft orders (staff-created `Spree::Order` rows, `status: 'draft'`,
`cart_id: nil`) already carry most of a negotiation engine: items,
addresses, manual fees and discounts that survive recalculation and freeze
at placement, notes, and invoice-later conversion. What's missing is the
one thing every negotiated B2B deal needs — **setting a unit price** ("10,000
units @ $7.20 for this order only, without touching the customer's price
list") — plus the machinery to start a negotiation from a customer's cart
without consuming it. This plan ships those **open-source mechanics**; the
customer-facing quotation product (lifecycle, send/accept, expiry, portal)
is Enterprise (`spree-enterprise-v2/docs/plans/b2b-quotes.md`; tier split
decided 2026-08-30 — same shape as company registration: OSS mechanisms,
Enterprise flow). Manual pricing is deliberately 6.0: it polishes the
brand-new draft-order surface (phone orders need it too) and rides with two
fixes in the same area; the copy service lands late in 6.0 so its Enterprise
consumer (quotes) needs nothing beyond 6.0 GA (retargeted 2026-08-30).

## Key Decisions (do not deviate without discussion)

- **`price_source: 'manual'` is the negotiated-price marker** (2026-08-30):
  the existing write-only provenance column gains its first reader.
  Setting a line's price through the admin API stamps `'manual'`; the two
  repricing paths gain guards — `Carts::PriceItems` skips manual rows, and
  `LineItem#should_update_price?` answers false for them — so a quantity
  change no longer silently re-prices a negotiated line from the pricing
  provider. `'manual'` is a **reserved key**: no pricing provider may
  register it.
- **Explicit revert, never silent.** `price: null` on the item update is
  the "back to catalog price" gesture — clears the marker and re-prices
  through the resolver. Nothing else may overwrite a manual price.
- **Price overrides are pre-placement only.** Once placed, money edits stay
  what they are today — fees and discounts — until the 6.1 order-change
  substrate owns post-placement amendments. Overrides answer "what is the
  agreed unit price", discounts answer "what concession is itemized on top";
  both freeze at placement through the existing paths.
- **`price_source` is admin-only surface.** Exposed on the admin line-item
  serializer (the dashboard marks negotiated lines and offers the revert);
  never on the store serializer — provenance is operational.
- **`Orders::Create` stamps `created_by`** (bug fix): the column and
  association exist but were never written, leaving staff drafts
  identifiable only by `cart_id IS NULL`.
- **The `payment_pending` docstring is corrected** (bug fix): it promises
  `payment_status: 'balance_due'`, but the status rollup has no such branch
  and produces `'none'`. The docstring now tells the truth; whether an
  unpaid placed order deserves a distinct rollup value is decided inside
  the wholesale-deposit work (`6.0-b2b-wholesale-shipping.md` phase 7),
  which is already reshaping that rollup — not here, and not twice.
- **`Spree::Orders::CreateFromCart` (6.0, late)** copies a customer's cart into a
  fresh draft order — line items with prices and `price_source` as they
  stand, addresses, customer/company, notes, metadata — **leaving the cart
  untouched** (a buyer who requests a quote keeps shopping). No money
  records, no fulfillments: those are rebuilt by the draft's own lifecycle.
  Deliberately a new service, not a reuse of `Carts::Complete`'s private
  copy helpers — that copy re-points money records and is one-shot by
  unique index; this one is an independent duplicate.

## Design Details

### Manual pricing (6.0)

- Admin surface: `price` accepted on `POST/PATCH
  /admin/orders/:id/items` (and the inline `items:` list on order create);
  `Orders::UpdateItem` gains a `price:` keyword. Guarded to incomplete
  orders.
- Model: setting a price through these paths assigns `price_source:
  'manual'`. Guards:

```ruby
# Carts::PriceItems#call — before resolving a row:
next if line_item.price_source == 'manual'

# LineItem#should_update_price?
!owner.completed? && price_source != 'manual'
```

- Dashboard: the draft-order items table's unit price becomes an editable
  input; a negotiated line shows a marker + "reset to catalog price"
  action; the order create form keeps quantity-only (override on the edit
  page, where the resolved price is visible to compare against).
- Specs pin the contract: a manual price survives quantity changes,
  recalculation, an external-pricing store's `confirm_prices`, and
  placement; revert re-prices; a provider registering key `'manual'`
  raises.

### Fixes (6.0)

`created_by` stamped from the authenticated admin in `Orders::Create`;
`payment_pending` docstring corrected to `payment_status: 'none'` with the
cross-reference to the deposit rollup work.

### Cart → draft order copy (6.0, late)

`Spree::Orders::CreateFromCart.call(cart:, created_by: nil, customer: nil)`
→ draft `Spree::Order` (no `cart_id` — it is NOT the completion copy and
must not claim the one-shot slot). Consumers: the Enterprise
request-a-quote flow (buyer-initiated), and plain admin "start a draft from
this cart".

## Migration Path

1. **6.0** — guards + admin `price` params + `'manual'` stamping + reserved
   key; `created_by`; docstring fix; dashboard editable price; admin
   serializer `price_source`.
2. **6.0, late** — `Orders::CreateFromCart` + specs; consumed by the Enterprise
   quote plan.

No data migration; every existing line has a provider or nil
`price_source` and behaves exactly as today.

## Constraints on Current Work

- **Nothing may reprice a `price_source: 'manual'` line** except the
  explicit revert; any new repricing call site must honor the guard.
- **`'manual'` never becomes a pricing-provider key.**
- **No post-placement price overrides** — placed-order money edits remain
  fees/discounts until the order-change substrate.
- **Store serializers never expose `price_source`.**
- Quote lifecycle, statuses, expiry, customer surfaces: Enterprise plan —
  don't grow them here.
