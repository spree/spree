# Backend-Agnostic CLI

**Status:** In Progress — 6.x renames, deprecation notices and the backend adapter are in; the Spree 7 removals and the Node adapter remain
**Target:** Spree 6.0 (renames + deprecations), Spree 7.0 (removals)
**Depends on:** `5.5-admin-api-cli.md`, `6.0-cli-configurator.md`
**Author:** Damian Legawiec
**Last updated:** 2026-10-01
**Tracking:** Linear — · GitHub —

## Summary
Spree 7 replaces the Rails backend with a Node one. The `spree` CLI is the main way developers drive a project, and several of its commands, flags and help texts are named after Rails tools (`spree rails`, `spree rake`, `spree bundle`, `spree rspec`, `spree routes`, `--reset-bundle`, `--ruby-name`). This plan makes the CLI's public surface describe *what* a developer wants (run tests, run a task, add an extension) rather than *which Rails tool* does it, so a project moves from Spree 6 to Spree 7 without relearning the CLI. Rails-named commands keep working through 6.x with a deprecation notice and are removed in 7.0.

## Key Decisions (do not deviate without discussion)
- **The neutral command is the contract; the backend is an implementation detail.** Every Rails invocation the CLI makes lives in `packages/cli/src/backend.ts`. Spree 7 replaces that file; command files do not change.
- **Deprecate, never break, in 6.x.** Old names stay registered as hidden commands or hidden flags, keep their exact behaviour, and print one line to stderr naming the replacement. Spree 7 removes them. stderr keeps captured output (`$(spree …)`) clean.
- **`spree exec` is the only escape hatch.** Anything only meaningful on Rails (`bin/rails runner`, `bundle outdated`, Rails's own generators) is reached as `spree exec bin/rails …`. No other Rails-named command is added.
- **Extensions are installed with `spree add <extension>`** (decided 2026-10-01), next to the existing `spree add dashboard`. On 6.x it adds the gem and runs the extension's install generator when it ships one. This replaces the `spree bundle add …` + `spree generate …:install` pair the docs used.
- **`spree generate` supports one generator: `api_resource`** (decided 2026-10-01). Model, decorator, subscriber, migration and Rails built-in generators still run in 6.x with a deprecation notice pointing at `spree exec bin/rails generate …`. Spree 7 ships its own `api_resource` and nothing else.
- **`spree task <name>` is kept and its task names become public.** The documented task names (`search:reindex`, `load_sample_data`, `setup:token`, `price_history:seed`, `channels:full_upgrade`) must keep working in Spree 7.
- **`spree rspec` becomes `spree test`.** Spree 7 runs its own test runner behind the same name.
- **Encryption key names are frozen.** `spree encryption init` writes `ACTIVE_RECORD_ENCRYPTION_*` into `.env`. Data encrypted with them is unreadable without them, so the Spree 7 backend must read these exact names and decrypt Rails-encrypted values. The variables are not renamed.

## Design Details

### Command mapping

| 6.0 (deprecated) | Replacement | Spree 7 |
| --- | --- | --- |
| `spree rails …` | `spree exec bin/rails …` | removed |
| `spree rake spree:<x> …` | `spree task <x> …` | removed |
| `spree rake <other> …` | `spree exec bin/rake …` | removed |
| `spree bundle add <gem>` | `spree add <gem>` | removed |
| `spree bundle <other> …` | `spree exec bundle …` | removed |
| `spree rspec …` | `spree test …` | removed |
| `spree routes` | `spree api endpoints` | removed |
| `spree generate <anything but api_resource>` | `spree exec bin/rails generate …` | removed |
| `spree generate <gem>:install` | `spree add <gem>` | removed |
| `spree migrate <raw args>` | `spree migrate` | raw args removed |
| `spree migrate:rollback STEP=n` | `spree migrate:rollback --steps n` | raw args removed |
| `spree build --reset-bundle` | `spree build --reset-deps` | removed |
| `spree plugin new --ruby-name` | `--backend-name` | removed |
| `spree plugin new --no-engine` | `--no-backend` | removed |

### Unchanged names, swappable internals
`init`, `dev`, `stop`, `restart`, `update`, `logs`, `open`, `eject`, `build`, `seed`, `sample-data`, `user create`, `api-key`, `console`, `shell`, `exec`, `task`, `test`, `migrate`, `migrate:status`, `migrate:rollback`, `db:reset`, `db:console`, `upgrade`, `encryption`, `api`, `auth`, `completion`. Their help text no longer mentions Rails, Rake, Bundler, Puma or Active Record.

### Backend adapter
`src/backend.ts` builds the command each neutral operation runs in the app container: console, test run, Spree task, seed, migrate, rollback, migration status, database reset, generator, extension install. Captured tasks (`spree:cli:*`, used by `init`, `user create` and `api-key`) go through the same module.

## Migration Path
1. **6.0** — neutral names, hidden deprecated aliases with notices, `spree add <extension>`, backend adapter, docs switched to neutral names.
2. **6.x** — move `user create` and `api-key list/revoke` onto the Admin API (`spree api` transport), which makes them backend-neutral without an adapter. `init` keeps a backend task for the first key.
3. **7.0** — remove the deprecated commands and flags, ship the Node `backend.ts`, move `upgrade`'s dependency bump from `bundle update` to the Node package manager.

## Constraints on Current Work
- Do not add CLI commands, flags or help text named after a Rails tool. New backend operations go into `src/backend.ts` behind a neutral command.
- Docs show neutral commands only. Rails-only steps use `spree exec bin/rails …`.
- New Spree rake tasks that developers run by hand belong in the `spree:` namespace so `spree task` reaches them, and their names are treated as public.
- Do not rename or stop reading the `ACTIVE_RECORD_ENCRYPTION_*` variables.
