# Channel → Markets Allowlist

**Status:** Design finalized 2026-08-28 — ready to implement
**Target:** Spree 6.0 (retargeted from 5.7 — the 5.7 release was cut, 5.6 → 6.0; 2026-08-09)
**Depends on:** `6.0-channels-catalogs-b2b.md` (Channel, shipped 5.5), `5.6-store-channel-context-and-key-binding.md` (channel binding + `/store/channel`), Markets (existing)
**Author:** Damian + Claude
**Last updated:** 2026-08-28

## Summary

Let a Channel be limited to a subset of the store's Markets. Today Channel (where you sell) and Market (where your customers are) are fully orthogonal request axes — `Spree::Current.channel` comes from key binding / `X-Spree-Channel`, `Spree::Current.market` from `x-spree-country` — and nothing can express "the wholesale channel only serves EU markets" or "the POS channel is domestic-only". This plan adds an optional allowlist: a join table between Channel and Market, empty meaning "all markets" (today's behavior). The industry validates the link from both directions: Vendure and Saleor merge channel and market into one primitive (per-channel currencies/zones), Shopify bridges its separate primitives with *channel markets* (a market conditioned on a sales channel) and since May 2026 routes per-market Shopify Payments entities through it; Medusa alone leaves the axes unlinked. Spree keeps its two first-class models and adds the constraint — which also composes with `6.0-payment-method-rules.md` (`MarketRule` on a channel-restricted market set) into "wholesale channel → EU markets → invoice payment".

**2026-08-28 design review.** The 2026-07-23 draft survives a full verification against post-catalogs main: nothing shipped since contradicts it, and two later decisions lean on it (`6.0-channel-delivery.md` borrows its empty-allowlist convention as "established"; the 2026-07-29 geo-modeling decision defers the channel axis here). Three corrections from verifying the wiring points — a callback-ordering fact, the move of order-market wiring into a shared concern, a third Store API leak path — plus four resolved questions are folded in below. The competing channel↔market path is gone: `CatalogAssignment` narrowed to buyer audiences on 2026-08-28 (its Channel/Market types were write-only), so this allowlist is the **only** channel↔market mechanism.

## Key Decisions (do not deviate without discussion)

- **A join table (`spree_channel_markets`), not a preference array.** Unlike rule config, this is a first-class admin-managed relationship that needs eager loading (`channel.markets`), serializer expansion, and Ransack — the same reasoning that made `ProductPublication` a table. `has_many :markets, through: :channel_markets`. Reaffirmed 2026-08-28 against the storage-by-cardinality convention (decisions.md 2026-08-06): that rule governs references *inside a rule record* (those stay `:array` preferences); a structural relationship read at request-resolution time is a table. The shipped `spree_channel_stock_locations` + `Channel#serves_location?` (2026-08-09, PR #14404) is the precedent this copies — same shape, same conventions, same memoized-id-list reader.
- **Empty allowlist = channel serves all store markets.** Matches the "empty = unrestricted" convention used by every rule preference. No backfill, zero behavior change on upgrade, and a single-market store never has to touch this.
- **Resolution degrades gracefully — no 422 for browsing.** A visitor whose country resolves to a market the channel doesn't serve gets the channel's default market experience (currency/locale/prices), exactly like a visitor from a country with no market at all.
- **Ship-to addresses are gated by delivery zones, never by markets (2026-08-28, resolves former open question 1).** No address-level rejection anywhere: an address in a country no zone covers gets zero delivery options at the delivery step (the storefront's natural "we don't deliver here"), and an address a zone does cover checks out in the channel-default market experience — merchants whose zones deliberately deliver wider than their market list keep working. A market-based address check would be a *third* geography gate: `MarketCountry#country_covered_by_shipping_zone` already guarantees every served market's countries are deliverable, and zone coverage already decides deliverability. The only hard rule is the purchase-level "market must be served by its channel" integrity validation below.
- **Per-channel default market is a persisted, nullable column (2026-08-28, resolves former open question 2 — reverses the draft's derived-only stance).** `spree_channels.default_market_id`, null = derived. Derivation when null: the store's default market when served, else the first allowed market by position. Read through **`Channel#resolved_default_market`** (house `resolved_*` naming, like `resolved_storefront_access`) — the raw `default_market` association is never consulted directly by resolution code, because the reader guards staleness: an explicit default is honored only while `serves_market?` says it is still served, else derivation takes over. Writes validate the market belongs to the channel's store and, when an allowlist exists, is on it. Deleting a market nullifies the column (`dependent: :nullify`).
- **The market filter reads the channel lazily (2026-08-28).** Verified empirically: on `Store::MarketsController`, `set_market_from_country` registers at before_action index 2 (via `V3::BaseController`'s `LocaleAndCurrency`) while `set_current_channel` registers at index 7 (`Store::BaseController`'s `ChannelResolution`) — the market callback fires five slots before the channel callback. The filter therefore calls the **memoized `current_channel` method**, which resolves on demand; no callback restructuring. The key-vs-header 422 conflict check still runs at its own slot and is unaffected (a request that will 422 does a little early work whose response is discarded). Precedent: `HttpCaching#cache_channel_fragment` already resolves the channel lazily the same way.
- **Purchase-level integrity lives in the shared concern, both hosts (2026-08-28).** The draft placed the "market must be served by its channel" validation on `Spree::Order`, but that wiring moved: `ensure_market_presence` / `resolve_market_from_currency` now live in `Spree::Purchase::Market`, included by **Cart and Order**. The validation and the channel-aware resolution go there — a cart rejects an off-channel market at assignment time, an order can never complete with one — with a shared-example battery run against both hosts (house convention for shared Cart/Order concerns). Skipped when either FK is nil, so jobs and imports without channel context keep working.
- **The Store API markets reference endpoints are the public surface of the restriction — all three actions.** `index`, `show`, the nested countries endpoints, **and `resolve`** (`?country=DE`, missed by the draft — it calls `market_for_country` directly and would otherwise leak unserved markets) scope through `current_channel.allowed_markets`. No `markets` embedding on the `/store/channel` serializer — the filtered reference endpoints already answer "which markets does this storefront serve" without creating a second source, and the no-enumeration rule (never leak other channels' config) stays intact.
- **HTTP caching needs no change (2026-08-28).** `HttpCaching` already folds `current_channel&.id` into every collection cache key and resource ETag, and `Vary` carries `x-spree-channel` — so channel-filtered market responses cache correctly by construction. Noted so nobody re-solves it.
- **Markets must belong to the channel's store** (validation on the join model), mirroring every cross-store guard in the codebase.
- **Deleting a market removes it from allowlists and nullifies any `default_market_id` pointing at it; a channel left with an empty allowlist reverts to "all markets".** Documented behavior + dashboard confirmation copy — not a deletion blocker (Market already blocks deleting the default/last market; further guards would make market cleanup miserable).
- **Management is dashboard-only** (markets multi-select + default-market select in the channel sheet + Admin API), consistent with the 2026-07-21 decision — no legacy Rails admin surface.

## Design Details

### Models

```ruby
# app/models/spree/channel_market.rb
module Spree
  class ChannelMarket < Spree.base_class
    belongs_to :channel, class_name: 'Spree::Channel', touch: true
    belongs_to :market, class_name: 'Spree::Market'

    validates :channel, :market, presence: true
    validates :market_id, uniqueness: { scope: [:channel_id, *spree_base_uniqueness_scope] }
    validate :market_belongs_to_channel_store
  end
end
```

Tables: `spree_channel_markets` — `channel_id` (null: false), `market_id` (null: false), timestamps, unique index on `(channel_id, market_id)` — plus `add_reference :spree_channels, :default_market` (nullable).

```ruby
# Spree::Channel additions — the reader trio copies the shipped
# serves_location? shape (memoized id list; empty = unrestricted).
has_many :channel_markets, class_name: 'Spree::ChannelMarket', dependent: :destroy
has_many :markets, through: :channel_markets, class_name: 'Spree::Market'
belongs_to :default_market, class_name: 'Spree::Market', optional: true

# @param market [Spree::Market, nil]
# @return [Boolean]
def serves_market?(market)
  return false if market.nil?
  return true if served_market_ids.empty?

  served_market_ids.include?(market.id)
end

# @return [Array<Integer>] ids of the markets this channel is limited to
def served_market_ids
  @served_market_ids ||= channel_markets.map(&:market_id)
end

# @return [ActiveRecord::Relation<Spree::Market>] markets this channel serves;
#   an empty allowlist means every market in the store.
def allowed_markets
  return store.markets.order(:position) if served_market_ids.empty?

  store.markets.where(id: served_market_ids).order(:position)
end

# @return [Spree::Market, nil] the explicit default while it is still served,
#   else the store default when served, else the first allowed by position.
def resolved_default_market
  explicit = default_market
  return explicit if explicit && serves_market?(explicit)

  store_default = store.default_market
  return store_default if store_default && serves_market?(store_default)

  allowed_markets.first
end
```

`Spree::Market` gains the inverses: `has_many :channel_markets, dependent: :destroy` + `has_many :channels, through:` (market deletion cleans allowlist rows) and `has_many :defaulting_channels, class_name: 'Spree::Channel', foreign_key: :default_market_id, dependent: :nullify` (market deletion clears explicit defaults).

### Request resolution

Two touch points, both already centralized:

1. **`Spree::Api::V3::LocaleAndCurrency#set_market_from_country`** — after resolving `store.market_for_country(country)`, discard the market unless `current_channel.serves_market?(market)` (visitor falls through to the channel default, same as an unmatched country today). Reads the lazy memoized `current_channel`, never `Spree::Current.channel` — see the callback-ordering decision above.
2. **`Spree::Current#market` fallback** — becomes channel-aware: `super || channel&.resolved_default_market || store&.default_market` (the channel branch only diverges when an allowlist or explicit default exists).

Derived effect: since Market drives currency/locale/tax-zone fallbacks, a restricted channel automatically constrains its sellable currency set to its allowed markets' currencies — converging on Vendure's `availableCurrencyCodes` / Saleor's per-channel currency without a second mechanism.

### Purchase integrity (Cart + Order, via `Spree::Purchase::Market`)

- `ensure_market_presence` resolves through `channel&.resolved_default_market` before the store default.
- Validation: `market must be served by the purchase's channel` when both FKs are set (skipped when either is nil — jobs/imports without channel context keep working). Guards against clients forcing an off-channel `market_id` through the API.
- `resolve_market_from_currency` (currency-change hook) picks from `channel&.allowed_markets || store.markets`.
- Shared-example battery (`a purchase constrained to channel-served markets`) run against **both** Cart and Order specs.

### Store API

- `Store::MarketsController` (`index`, `show`, **`resolve`**) + `Markets::CountriesController` scope through `current_channel.allowed_markets` instead of `current_store.markets`. `resolve` with a country whose market the channel doesn't serve is a 404 — indistinguishable from a country with no market, which is the point. These endpoints are guest-accessible reference data (`allow_guest_storefront_access!`) — filtering them is the entire public contract; nothing else changes shape. HTTP caching is already channel-keyed (see Key Decisions).
- `GET /store/channel` (from `5.6-store-channel-context-and-key-binding.md`) is unchanged.

### Admin API v3

- Channel create/update accepts `market_ids: []` (prefixed `mkt_…` IDs, normalized + store-scope-validated on write; empty array clears the allowlist → all markets) and `default_market_id` (nullable, prefixed, resolved through `current_store.markets` exactly like `default_catalog_id`; null clears the override → derived).
- Admin channel serializer exposes `market_ids` + `default_market_id` (prefixed) and `many :markets` via `expand=markets`.
- No new endpoints — the allowlist is part of the channel aggregate, matching how publications are managed through channel action endpoints rather than join-table CRUD.

### SDK & Dashboard

- `@spree/admin-sdk`: `market_ids` + `default_market_id` on the channel resource types and params; typelizer regeneration.
- Dashboard channel sheet: a "Markets" multi-select defaulting to "All markets" when the allowlist is empty, plus a "Default market" select listing the allowed markets with a blank "Store default" option; confirmation copy when clearing the last allowlist entry ("this channel will serve all markets"). Translation keys in all six dashboard locale files.
- `@spree/sdk` (Store): no changes — clients keep consuming `/store/markets`, which is now channel-scoped transparently.

## Migration Path

Additive only:

1. One migration: create `spree_channel_markets` + add nullable `default_market_id` to `spree_channels`. No backfill — every channel starts unrestricted with a derived default.
2. Models + resolution changes ship together (behavior only diverges once an admin restricts a channel or sets an explicit default).
3. Admin API + dashboard UI.

The 5.6 wholesale seed channel stays unrestricted by default; the sample-data story ("wholesale serves EU markets only") is optional polish once `6.0-payment-method-rules.md` lands its seed changes.

## Constraints on Current Work

- **New market-dependent features must resolve through `channel.allowed_markets` / `Channel#serves_market?`** when a channel context exists — don't reach for `store.markets` directly in request-path code.
- **Don't expose other channels' market allowlists through any Store API surface** — the no-enumeration rule from `5.6-store-channel-context-and-key-binding.md` extends to this relationship.
- **`default_market_id` is the only market column on `spree_channels`** (2026-08-28 — reverses the draft's "no market columns" line). Consumers read `Channel#resolved_default_market`, never the raw `default_market` association: the association's value can be stale against the allowlist, and only the resolver guards that.
- **No market-based ship-to or address validation, anywhere.** Delivery-zone coverage is the one geographic gate (see Key Decisions); a checkout feature needing "can we sell here" asks the zones, not the markets.

## Open Questions

None. Both 2026-07-23 questions were resolved on 2026-08-28 — ship-to gating went to delivery zones, the per-channel default became a persisted column — and moved into Key Decisions above.
