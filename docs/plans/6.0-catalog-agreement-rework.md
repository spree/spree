# Catalog Agreement Rework (Binding Inversion + Audience-Rule Retirement)

**Status:** Draft — design finalized 2026-08-30 (extracted 2026-08-30 from the amendment block in `6.0-b2b-companies-and-catalogs.md`, whose Implemented status was hiding this unbuilt work), nothing built
**Target:** Spree 6.0 — sequence Wave 1: everything catalog-shaped builds on the inverted binding, and the leak fix touches unreleased code
**Depends on:** B2B Companies & Catalogs (6.0-b2b-companies-and-catalogs.md — the shipped catalogs this reworks), PriceList system (released)
**Author:** Damian + Claude
**Last updated:** 2026-08-30

## Summary

The implementation half of the one-question-per-entity doctrine (decisions.md
2026-08-30): the Catalog becomes the **commercial agreement** — the one
object answering "what does this buyer see, pay, and buy on" — and the
Catalog ↔ PriceList relationship is reshaped accordingly. The binding
inverts (`spree_price_lists.catalog_id` replaces
`spree_catalogs.price_list_id`), which closes a real leak in the shipped
unreleased design; the audience-shaped price rules
(`PriceRules::CustomerGroupRule`, `UserRule`) are retired in favor of
catalog assignment; and the dashboard flips to **catalog-first, one-go
setup**. The related term/pricing features build on this: the quantity
plan's catalog terms (`6.0-b2b-quantity-rules.md`) and the automatic ±%
pricing card (`6.0-price-list-automatic-pricing.md`) both land on the
catalog page this rework establishes.

## Key Decisions (do not deviate without discussion)

- **The binding inverts: a price list is standalone or owned by exactly one
  catalog** (2026-08-30, interactive review). `spree_price_lists.catalog_id`
  (nullable) replaces `spree_catalogs.price_list_id`; generic rule matching
  simply skips owned lists (`WHERE catalog_id IS NULL`). This closes the
  leak: the shipped derived exclusion set (`Catalog.bound_price_list_ids`)
  reads **active** catalogs only, so deactivating a catalog dropped its —
  typically rule-less — list back into generic matching, pricing the whole
  store. With the FK, a deactivated catalog's list goes dormant; detaching
  a list is an explicit act behind a dashboard warning ("this list will
  start matching by its own rules"). Sharing one list across catalogs is
  lost — one catalog serving many audiences through assignments is the
  replacement.
- **Audience price rules retire; context rules stay.**
  `PriceRules::CustomerGroupRule` and `PriceRules::UserRule` duplicated
  catalog assignment with different, silent precedence — deprecated in 6.0
  with the standard one-release bridge and a data task converting each such
  list into an assortment-less catalog assigned to the audience and owning
  the list (a `UserRule` list maps to a single-member customer group).
  `PriceRules::ChannelRule` is **grandfathered**: kept working, nothing new
  builds on it, the forward path is the channel's default catalog owning an
  assortment-less list. `MarketRule` (carries VAT restatement) and
  `VolumeRule` are context-shaped and stay first-class.
- **Because catalogs are unreleased (6.0 edge), the catalogs side rewrites
  in place** — the create-catalogs migration drops its `price_list_id`
  reference, no bridge, per the companies-plan precedent. The
  `spree_price_lists` side is a **released** table and gets an ordinary
  additive migration for `catalog_id`.
- **The dashboard flips to catalog-first, and setup is one go.** The
  catalog page becomes the agreement editor — audience assignments,
  assortment, an inline pricing card for its owned list, terms — plus a
  **products-with-prices view** showing, per product, assortment membership
  and the resolved price with its source (explicit / automatic / base), so
  assortment↔pricing divergence is visible instead of
  discoverable-by-accident. The New catalog flow takes name, audience,
  assortment, and a pricing choice (base prices / ±% adjustment / fixed
  prices); the admin catalog create/update endpoints accept an inline
  `price_list` payload for the owned list, so standing up an agreement
  never requires visiting the price-lists page.

## Design Details

- Associations flip: `PriceList belongs_to :catalog (optional)` /
  `Catalog has_one :price_list`; `Catalog.bound_price_list_ids` and its
  `Spree::Current` memoization are deleted — the resolver's
  `applicable_price_lists` filters `catalog_id: nil` in SQL, and
  `catalog_price_lists` reads the association. Only **active** catalogs
  still claim their list in the resolution walk (unchanged semantics,
  now leak-free on the exclusion side).
- Deprecation bridges: creating a new `CustomerGroupRule`/`UserRule` warns
  (removed 6.1); existing rows keep matching through the bridge release so
  un-migrated stores don't lose pricing mid-upgrade.
- Data task (`spree:upgrade:migrate_audience_price_rules_to_catalogs`, in
  the 6.0 manifest): audience-only lists convert cleanly; a list mixing
  audience and context rules (or `match_policy: all` across both) is
  reported for manual review rather than guessed at — a wrong automatic
  conversion here is a silent price change.
- Admin API: catalogs create/update accept `price_list: {...}` (create or
  update the owned list inline); the price-lists endpoints keep working for
  standalone lists; detach = `price_list: null`-style explicit action.
- Dashboard: catalog page (agreement editor + products-with-prices view +
  detach warning), New catalog wizard, price-list page banner for owned
  lists linking to their catalog.

## Migration Path

1. **Schema** — rewrite the catalogs migration in place (drop
   `price_list_id`); additive `catalog_id` on `spree_price_lists`; edge
   worktrees rebuild the template DB.
2. **Model + resolver** — association flip, SQL-level owned-list exclusion,
   delete the derived set + memoization; specs pin the leak (a deactivated
   catalog's rule-less list prices nobody).
3. **Rule retirement** — deprecation warnings + bridge, the data task,
   types-discovery marking.
4. **API + dashboard** — inline `price_list` payload, agreement editor,
   products-with-prices view, wizard, detach warning. (The pricing card's
   ±% controls and the Terms card arrive with their own plans on this
   surface.)

## Constraints on Current Work

- **No new code reads `spree_catalogs.price_list_id`** or
  `Catalog.bound_price_list_ids` — the FK on the list is the one binding.
- **No new features build on `PriceRules::CustomerGroupRule`/`UserRule`**
  (deprecated) **or `ChannelRule`** (grandfathered) — audience targeting is
  catalog assignment; channel pricing is the default catalog.
- Catalog-page features (terms, pricing card) mount on the agreement
  editor this plan establishes — no parallel catalog editing surfaces.

## Open Questions

None — the design questions were resolved in the 2026-08-30 entity review
(decisions.md). The mixed-rule-list conversion policy (report, don't guess)
is deliberate, not open.
