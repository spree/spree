Klaviyo is a marketing automation platform for email and SMS. Connecting your store sends Klaviyo what it needs to segment customers and run flows: customer profiles, newsletter sign-ups, and every order from purchase to refund, under Klaviyo's standard ecommerce metric names. Klaviyo's flow templates, metric mapping and lifetime-value reports recognise the data without extra setup.

Two parts work together:

- **Spree's server** sends what only it knows: profiles, newsletter sign-ups and removals, purchases, cancellations, shipments and refunds.
- **Your storefront** loads Klaviyo's script, which sends browsing events and Started Checkout, and tells Klaviyo who is shopping.

<Info>
  You need an existing Klaviyo account to connect this integration.
</Info>

## Installation

<CodeGroup>

```bash Spree CLI (Docker)
spree add klaviyo
```

```ruby Without Spree CLI
# server/Gemfile — use the same version requirement as your `spree` gem, then run `bundle install`
gem 'spree_klaviyo', '>= 6.0.0'
```

</CodeGroup>

The Spree CLI restarts the server for you. Without it, restart the server yourself. The integration registers itself, so there is nothing to generate and no migrations to run.

The Klaviyo SDK uses libcurl, which Spree's server image already includes.

## Create a private API key

In Klaviyo, go to **Settings → Account → API keys** and click **Create Private API Key**.

![The API keys page in Klaviyo's settings](/images/integrations/klaviyo/3.create_private_key.png)

Choose **Custom Key** and give it these scopes:

| Scope | Access | Used for |
|---|---|---|
| Events | Read/Write | Order and refund events |
| Lists | Read/Write | Checking the connection, newsletter sign-ups |
| Profiles | Read/Write | Customer profiles |
| Subscriptions | Read/Write | Email-marketing consent |
| Data Privacy | Write | Deleting the profile of a customer you erase |

![Klaviyo's form for a new private key with custom scopes](/images/integrations/klaviyo/4.configure_private_key.png)

Turning the integration on reads your newsletter list, so a wrong key, a key without the Lists scope or a wrong list id stops it with Klaviyo's own message. A key missing one of the other scopes still connects. The first call that needs the missing scope is then refused and reported to your error tracker, so check the scopes before you connect.

## Connect Klaviyo

In the Spree admin dashboard, open **Settings → Integrations**, find Klaviyo under Marketing and add it. Enter:

- **Klaviyo private API key**: the key you just created.
- **Default newsletter list id**: the Klaviyo list newsletter sign-ups go to. Find it in Klaviyo under **Audience → Lists & segments**, in the list's settings.

Save, then turn the integration on. Only an active integration sends anything to Klaviyo.

## Newsletter sign-ups and double opt-in

Klaviyo runs the newsletter opt-in. Every sign-up goes to Klaviyo at once, and the list's own opt-in setting, which you choose in Klaviyo, decides what happens next:

- **Double opt-in**: Klaviyo emails its confirmation and adds the address once the shopper clicks the link. Design the confirmation email in Klaviyo, under the list's settings. Many markets expect double opt-in, including Germany, Austria, Switzerland and much of the EU.
- **Single opt-in**: Klaviyo adds the address at once, and nobody sends a confirmation.

While the integration is active, Spree does not send its own newsletter confirmation in either case. A signed-in customer who ticks "email me" also confirms through Klaviyo's email on a double opt-in list, because the list's setting covers every source.

When a subscription is removed (the customer opts out, staff delete the subscriber, or you erase the customer), Spree unsubscribes the address, which revokes its email-marketing consent in Klaviyo. Klaviyo keeps consent per account, not per list. Stores that share one Klaviyo account therefore share consent: an unsubscribe sent for one store stops marketing email from all of them.

Confirmations and unsubscribes made in Klaviyo are not reflected in Spree. Klaviyo is the record of marketing consent for your store.

## What Spree sends

| In Spree | In Klaviyo |
|---|---|
| A customer is created or updated | The profile is created or updated |
| A newsletter sign-up | The address is subscribed to your list |
| A newsletter subscription is removed | The address is unsubscribed |
| An order is placed | The profile is updated from the order, plus Placed Order and one Ordered Product per line |
| A package ships | Fulfilled Order, for that package |
| An order is canceled | Canceled Order |
| A return is refunded | Return Refunded, unless nothing was refunded |
| A customer is erased | The profile is deleted, 30 minutes later |

A split checkout on a marketplace is one purchase: it sends one Placed Order with the whole basket, and its sellers' orders send none. Shipments and cancellations are still sent per seller's order.

Each profile carries the customer's email, name and location from their billing address, plus an external id so Klaviyo keeps one profile when the customer changes their email. A guest is identified by email alone.

### Event properties

The events use the property names of Klaviyo's ecommerce guide, so Klaviyo's templates can use them directly:

- **Placed Order** and **Canceled Order**: `OrderId`, `Items`, `ItemNames`, `Categories`, `DiscountCode`, `DiscountValue`, `Subtotal`, `ShippingTotal`, `TaxTotal`, `Total`, `BillingAddress`, `ShippingAddress` and `NotifyCustomer`.
- **Ordered Product**: one line's `ProductID`, `SKU`, `ProductName`, `Quantity`, `ItemPrice`, `RowTotal`, `ProductURL`, `ImageURL` and `Categories`, plus `OrderId`.
- **Fulfilled Order**: `OrderId`, `TrackingNumber`, `TrackingURL`, the package's `Items` and `ItemNames`, `ShippingAddress` and `NotifyCustomer`.
- **Return Refunded**: `ReturnNumber`, `OrderId`, the returned `Items`, `ItemNames`, `RefundedTotal` and `Currency`.

Each item in `Items` carries the same fields as Ordered Product. `OrderId` is the order number the customer was given: for a split checkout, that is the purchase's number. Every event is sent once, even when Spree retries it.

### Lifetime value

Placed Order, Ordered Product, Fulfilled Order and Canceled Order carry a value, so Klaviyo counts revenue and subtracts a cancellation from the customer's lifetime value. Refunds never reduce lifetime value: Return Refunded carries the refunded total as a property, not as revenue. On a marketplace, a seller's cancellation does not reduce it either, because it cannot be matched to the purchase's Placed Order. Treat lifetime value in Klaviyo as approximate for marketplace stores.

## Let Klaviyo send your order emails

Four switches in the integration form hand an order email over to Klaviyo. While a switch is on, Spree stops sending that email, and a Klaviyo flow sends it instead:

| Switch | Spree stops sending | Build the flow on |
|---|---|---|
| Klaviyo sends the order confirmation | The order confirmation | Placed Order |
| Klaviyo sends the cancellation email | The cancellation email | Canceled Order |
| Klaviyo sends the shipping confirmation | The shipping confirmation | Fulfilled Order |
| Klaviyo sends the refund email | The refund email | Return Refunded |

Klaviyo receives each event exactly when Spree would have sent the email, so turning a switch on neither adds nor loses an email.

<Warning>
  Build and turn on the flow in Klaviyo before you turn its switch on. Otherwise customers get no email at all.
</Warning>

Staff can place an order for a customer, cancel one or mark a package shipped without notifying the customer, and Spree then skips its email. Placed Order, Canceled Order and Fulfilled Order carry that choice as `NotifyCustomer`. Add a flow filter on `NotifyCustomer` equals `true` to each flow that replaces a Spree email, because the flow cannot know otherwise.

Keep in mind:

- **Resend confirmation** in the dashboard sends nothing for an email Klaviyo has taken over.
- Emails whose link Spree must later redeem always stay with Spree: password resets, data exports and data request confirmations, digital downloads, payment links and company invitations.
- A storefront that sends its own emails from webhooks, such as the reference storefront's Resend option, is not affected by these switches. Turn those emails off in the storefront.

## Stores coming from the 1.x extension

The 1.x extension sent each customer's database id as the profile's external id. Turn on **Match profiles by database id** so the profiles it created keep matching. A new Klaviyo account should leave it off: profiles then carry the customer's Spree id (`cus_…`), which you can look up in the dashboard and the API. Stores that share one Klaviyo account should use the same setting.

## Storefront tracking

The Next.js storefront loads Klaviyo's script when `KLAVIYO_COMPANY_ID` is set. Use your account's six-character public API key, shown under **Settings → Account → API keys** in Klaviyo:

```bash .env
KLAVIYO_COMPANY_ID=AbC123
```

The storefront reads it on the server, so changing it needs no rebuild. Leave it empty to turn Klaviyo off. With the script loaded, the storefront sends:

- **Viewed Product** on a product page, and **Added to Cart** when the shopper adds it.
- **Started Checkout** when checkout opens for a shopper who already gave their email, otherwise once they enter it. Its `CheckoutURL` opens the storefront's cart page.
- **Active on Site**, which Klaviyo's script sends by itself.

The storefront also identifies the shopper by email when they sign in, sign up or enter their email at checkout. That joins the browser's anonymous history to the profile Spree sends, since only the browser holds Klaviyo's visitor cookie.

The reference storefront has no newsletter sign-up form. If yours adds one, call Klaviyo's `identify` with the email when the form is submitted, as well as subscribing through Spree:

```typescript
window.klaviyo?.identify({ email })
```

Ad blockers and declined cookie consent stop Klaviyo's script, and with it some browsing events and abandoned-checkout emails. Asking for cookie consent before loading the script is the storefront's job, as it is for Google Tag Manager. A custom storefront sends these events itself.

## Erasing a customer

When you erase a customer, Spree asks every active Klaviyo integration, in every store, to delete the person's profile. The request goes out 30 minutes after the erasure, after the unsubscribes of their newsletter subscriptions. Deletion removes the profile's whole history in Klaviyo and cannot be undone, which is what erasure requires.

Deletion needs the **Data Privacy (write)** scope. Without it, Klaviyo refuses the request with 403, and the failure is only reported to your error tracker. The profile stays in Klaviyo, so check the scope.

After an erasure, nothing more is sent for that person, even when their retained orders are later canceled or shipped.
