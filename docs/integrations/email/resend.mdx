[Resend](https://resend.com) is a transactional email service built for developers, with a deliberately small setup: add a domain, create an API key, and send. It is a good default for a new Spree store that wants working email quickly without a long account review.

Spree talks to Resend over plain SMTP, so there is nothing to install — see [Emails](/developer/providers/emails) for how the configuration works.

## Configuration

```bash
SMTP_HOST=smtp.resend.com
SMTP_PORT=587
SMTP_USERNAME=resend
SMTP_PASSWORD=re_your_api_key
SMTP_FROM_ADDRESS=orders@yourstore.com
```

The username is the **literal string `resend`** — not your email address and not the API key. The API key goes in the password field.

Resend also accepts ports 25 and 2587 for STARTTLS. Ports 465 and 2465 are implicit TLS, which Spree does not use, so stay on 587.

## Getting an API key

1. Open the Resend dashboard and go to **API Keys**.
2. Create a key with sending permission.
3. Copy it immediately — the full value is shown only once. Keys start with `re_`.

## Authenticating your domain

Go to **Domains → Add Domain**, enter your sending domain, and add the records Resend generates at your DNS host:

- **DKIM and SPF** as `TXT` records, which prove the mail is really yours.
- An **MX or CNAME** record for the sending subdomain.
- A **DMARC** record, which Resend recommends adding once the domain verifies.

Copy the values exactly as Resend generates them. Once the domain shows as verified, set `SMTP_FROM_ADDRESS` to an address on it.

<Warning>
**Until you verify a domain, you can only email yourself.** An unverified account sends from `onboarding@resend.dev`, and Resend restricts that test sender to the address on your own Resend account — anything else is refused with "You can only send testing emails to your own email address". A store in this state appears to work while no customer ever receives an order confirmation, so verify your domain before going live.
</Warning>

<Note>
Resend's free tier allows 3,000 emails a month but also caps sending at **100 a day**. A busy day of confirmations and shipping notices can reach that ceiling well before the monthly allowance, so check the daily figure rather than the monthly one when sizing a plan.
</Note>
