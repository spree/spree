---
title: "Product Types"
description: "Learn how to use product types in Spree Commerce to pre-fill new products and control how they can be delivered."
---

A product type is a template for products that share similar characteristics. A T-Shirt type carries the option types every shirt needs, the categories they belong in, the data fields associated with them, and the delivery profile they ship on. Create a product using that type, and all of these will be pre-configured.

Using product types doesn't just save time. It guarantees consistency across the product catalog. Every shirt ends up built the same way. Left to themselves, one person might add a Size option and another adds Sizing, one fills in the fabric composition and another forgets, and six months later the catalog cannot be filtered or reported on properly because no two products agree on what they carry. A type settles those decisions once, so the twentieth product matches the first, without anybody having to remember or check how the first was set up.

That consistency is worth most when the catalog is large, or when more than one person adds to it. It is also what makes a type the right place to make certain data fields compulsory: mark it required here and nobody can save a product of that type without it.

To manage product types, navigate to **Settings → Product types**, under the **Shipping & delivery** group.

![The Product types list, showing each type and how many products carry it](/docs/images/user/settings/product-types/1-product-types-overview.png)

## How to Create a Product Type

Click **Add product type**.

![The New product type panel](/docs/images/user/settings/product-types/2-new-product-type.png)

- **Name** - What the type is called, such as T-Shirt.
- **Option types** - Added to products created with this type. Used to create variants.
- **Categories** - Added to products created with this type.
- **Delivery profile** - Stamped onto products created with this type, and what decides the delivery options offered at checkout. Choose **Store default profile**, or a specific [<u>delivery profile</u>](/user/settings/delivery-profiles) for goods that ship differently.

### Custom fields

At the foot of the panel you can attach [<u>custom fields</u>](/user/settings/custom-fields) to the template, so that every product of this type carries them.

Each field you attach can be marked **required**, which means a product of this type cannot be saved until somebody fills it in. That is the difference between hoping a field gets filled and knowing it has been.

Drag the fields into the order you want. That order is the order they appear on the product form, so group them in a way that makes sense rather than leaving them in the order you happened to add them.

<Note>Only custom fields that already exist can be attached here. Create them first in [<u>Custom Fields</u>](/user/settings/custom-fields), making sure to set **Applies to** to Products.</Note>

Click **Create product type**.

<Warning>Most of what a type carries is a starting point rather than a rule. Option types, categories and the delivery profile are copied onto a product as it is created, and the product is free to differ afterwards. Required custom fields are the exception: those are enforced every time the product is saved.</Warning>

## How to Edit a Product Type

Open the row menu and choose **Edit** to change the name, the option types, the categories, the delivery profile, or the custom fields.

### What reaches products that already exist

Editing a type does not rewrite the products already using it. What changes, and for whom, depends on what you edited:

- **Option types and categories** shape products created from now on. Products that already carry the type keep what they have.
- **The delivery profile** is stamped on at creation, so changing it never moves products that already carry the type.
- **Custom fields** show on every product of that type immediately, including ones that already exist.

<Warning>Marking a custom field required applies to every product of that type, not only new ones. An existing product missing that value cannot be saved again until somebody fills it in, so add a required field before the catalog is large, or expect to backfill data.</Warning>

### Applying changes to existing products

When you do want a change to reach products that already carry the type, use **Apply to existing products**. The button shows how many products it will affect.

This adds the type's missing option types and categories to those products. Nothing is removed, so a product that has drifted from the template keeps whatever it gained along the way.

<Note>This is additive only. It cannot be used to strip option types or categories from products that should no longer have them.</Note>

## How to Delete a Product Type

Open the row menu and choose **Delete**.

<Warning>A type still used by products cannot be deleted. Move those products onto another type first, or the delete is refused.</Warning>
