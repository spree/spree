All monetary values in the Store API are returned as **decimal strings**, never JSON numbers, written with exactly the decimal places of their currency: `"29.99"` in USD, `"1.500"` in Kuwaiti dinar, `"1000"` in yen. Unit prices may carry up to four decimals (`"0.0125"`). This preserves decimal precision and avoids the rounding errors of JSON numbers. A currency's decimal places are its `decimal_places` (see [below](#currency-decimal-places)).

## Response Format

Every monetary field is a decimal string, with its currency on the record or on the record it belongs to (an order's line items, payments and fulfillments are in the order's currency):

```json
{
  "currency": "USD",
  "total": "129.99",
  "item_total": "99.99",
  "delivery_total": "10.00",
  "tax_total": "20.00"
}
```

Format each amount for the customer reading it, in their language and in the currency the amount is in. An order or cart carries both (`currency`, `locale`); before checkout, use the current market's (`currency`, `default_locale`) or the price's own `currency`. See [Working with Amounts](#working-with-amounts) for examples.

<Warning>
**The `display_*` fields are deprecated and will be removed in Spree 6.1.** Each monetary field still has a pre-formatted copy (`display_total` beside `total`), formatted in the request's language. Format the amount beside it instead. The API reference marks these fields as deprecated, and the SDK types strike them through. Labels such as `display_name` are not affected.
</Warning>

## Affected Types

This convention applies to all monetary fields across all resources:

| Resource | Monetary Fields |
|----------|----------------|
| **Cart / Order** | `total`, `item_total`, `delivery_total`, `tax_total`, `adjustment_total`, `discount_total`, `included_tax_total`, `additional_tax_total`, `fee_total`, `store_credit_total`, `gift_card_total`, `amount_due` |
| **Line Item** | `price`, `total`, `adjustment_total`, `discount_total`, `included_tax_total`, `additional_tax_total`, `pre_tax_amount`, `discounted_amount`, `compare_at_amount` |
| **Fulfillment** | `cost` |
| **Payment** | `amount` |
| **Gift Card** | `amount`, `amount_used`, `amount_authorized`, `amount_remaining` |
| **Store Credit** | `amount`, `amount_used`, `amount_remaining` |
| **Price** | `amount`, `compare_at_amount` (unit prices, up to four decimals) |

Rates, such as a tax line's `rate`, are decimal strings too, without trailing zeros (`"0.23"`).

## Currency decimal places

Each currency the store sells in (`GET /api/v3/store/currencies`) carries `decimal_places`, from ISO 4217: `2` for USD and EUR, `0` for JPY, `3` for KWD. Every amount in that currency is written with that many decimals.

## Working with Amounts

`Intl.NumberFormat` reads the decimal string exactly, so pass it the amount as it arrives, with the currency of the record it belongs to.

### Order and cart totals

An order carries its own `currency` and the `locale` the customer shopped in, so its receipt reads the same however the store changes later.

<CodeGroup>

```typescript SDK
import { compareMoney, sumMoney } from '@spree/sdk'

const order = await client.orders.get('or_abc123', {}, { token });

const money = new Intl.NumberFormat(order.locale ?? 'en', { style: 'currency', currency: order.currency });

money.format(order.total);          // "€129.99" for an order in euros, read in English
money.format(order.delivery_total); // "€10.00"

// Calculate on the strings, exactly
const subtotal = sumMoney(order.items.map((item) => item.total), order.currency); // "129.99"
const isFree = compareMoney(order.total, '0') === 0;
```

```javascript JavaScript
const order = await response.json();

const money = new Intl.NumberFormat(order.locale ?? 'en', { style: 'currency', currency: order.currency });
element.textContent = money.format(order.total); // "€129.99"

// Calculate on the raw strings with a decimal library, never parseFloat:
// 0.1 + 0.2 is 0.30000000000000004 as a JSON number.
```

</CodeGroup>

### Product prices

Before there is a cart, prices are in the customer's market. Resolve the market once and format every price with it; each price also carries its own `currency`.

<CodeGroup>

```typescript SDK
const market = await client.markets.resolve('DE');
const money = new Intl.NumberFormat(market.default_locale, { style: 'currency', currency: market.currency });

const product = await client.products.get('spree-tote', {}, { currency: market.currency, locale: market.default_locale });

money.format(product.price.amount);            // "29,99 €"
if (product.price.compare_at_amount) {
  money.format(product.price.compare_at_amount); // "39,99 €"
}
```

```javascript JavaScript
const headers = { 'X-Spree-API-Key': 'pk_xxx' };
const market = await (await fetch('/api/v3/store/markets/resolve?country=DE', { headers })).json();
const product = await (await fetch('/api/v3/store/products/spree-tote', {
  headers: { ...headers, 'X-Spree-Currency': market.currency, 'X-Spree-Locale': market.default_locale },
})).json();

const money = new Intl.NumberFormat(market.default_locale, { style: 'currency', currency: market.currency });
element.textContent = money.format(product.price.amount); // "29,99 €"
```

</CodeGroup>

<Tip>
Calculate on the raw strings with the SDK's `sumMoney`, `subtractMoney`, `multiplyMoney`, `compareMoney` and `isZeroMoney`, which work on decimal strings exactly, and pass the string straight to `Intl.NumberFormat` to display it. Never convert an amount to a JSON number.
</Tip>
